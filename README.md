# PolyTools

PowerToys-style Windows utility collection, built with **Go + Wails v3** — a single
process hosts every module and a WebView2-based settings UI (Fluent design).

Windows only.

## Commands

```bash
wails3 dev      # dev mode (hot reload, devtools)
wails3 build    # production build → bin/polytools.exe
go build ./...  # compile check (build/ios is Android-only scaffolding; ignore its error)
```

## Architecture

```
main.go                     app bootstrap: window (frameless + Mica), system tray, single instance
internal/
  core/
    module.go               Module interface, Info/SettingField schema, categories
    basemodule.go           BaseModule: state + enable/disable/setting callbacks
    registry.go             module registry, enable/setting dispatch, change events
    store.go                JSON persistence (%LOCALAPPDATA%\PolyTools\settings.json)
  win32/win32.go            Win32 helpers (SetThreadExecutionState, TOPMOST, …)
  modules/
    modules.go              RegisterAll — the module list
    real.go                 implemented modules (Awake, Always On Top)
    placeholders.go         catalog-only modules (Available=false → "Coming soon")
  services/polytools.go     Wails-bound service consumed by the frontend
frontend/                   React + TypeScript + @fluentui/react-components (Fluent v9)
  src/i18n/                 en/ko dictionaries + Translator context (module strings
                            via module.<key>.* / set.<key>.<field>.* keys, English fallback)
  bindings/                 generated by `wails3 build/dev` — do not edit
test/                       manual Go probes (hotkeyprobe, topmostprobe)
docs/ROADMAP.md             per-module design notes + feasibility analysis
```

## Adding a module

```go
// in internal/modules/
reg.Register(core.NewModule(core.Info{
    Key: "my-tool", Name: "My Tool", Description: "...",
    Icon: "Pin",           // Fluent icon name → frontend/src/components/ModuleIcon.tsx
    Category: core.CategorySystem,
    Available: true,       // false → listed but disabled, "Coming soon" badge
    Settings: []core.SettingField{
        {Key: "hotkey", Label: "Activation shortcut", Type: core.SettingShortcut, Value: "ctrl+alt+x"},
    },
}).WithHandlers(onEnable, onDisable).WithSettingHandler(onSetting))
```

- Enable/disable + setting values persist automatically via the store.
- Global hotkeys: `app.GlobalShortcut.Register("ctrl+alt+t", fn)`
  (`super` = Win key on Windows).

## Platform notes

- Frameless window + `BackgroundTypeTranslucent` + `BackdropType: Mica`;
  titlebar drag region uses CSS `--wails-draggable: drag`, caption buttons use
  `--wails-non-client-region: minimize|maximize|close` (needs
  `NonClientRegionSupport: true`) — keeps native Snap-Layout flyout.
- Close → hides to system tray (`WindowClosing` hook + `Cancel()`).
- Shell-integration features (modern Win11 context menu, preview handlers)
  cannot be done in pure Go — would need a separate COM DLL component.
